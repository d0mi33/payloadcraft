01the problem

Walls stopped working

Traditional security worked like a castle: build a strong wall, check people at the gate, and trust whoever is inside. Zero trust works like an airport where every door checks your badge, every time, no matter how you got into the building.

old model · perimeter

One stolen password or one compromised machine and the attacker is "inside". From there they can move sideways to anything, because inside means trusted.

new model · zero trust

There is no "inside". Every request, even from a neighboring system, must prove who it is and that it is allowed. A breach stays small because each hop is checked again.

bug → working exploit
before
months
with AI
hours, for a few dollars

Why now? Frontier AI models can turn a vulnerability into a working attack in hours instead of months. Attackers also use them to read a security patch and work backwards to the hole it fixed. Defenders get the same speed, but only if their systems were designed expecting a breach. Walls and slow patch cycles can't keep up.

03what changes

Why agents are different

A normal program does exactly what its code says. An agent reads a goal in plain language, picks its own tools, and runs many steps without asking. That creates five problems older security tools weren't built for.

key idea

Most agent attacks don't break any permission. The agent uses access it legitimately has, in a way nobody intended. That's why classic access control alone doesn't stop them, and why monitoring behavior matters as much as blocking.
